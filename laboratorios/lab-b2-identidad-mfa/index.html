Laboratorio B2 — Identidad y acceso: autenticación centralizada y segundo factor

Objetivo. Al terminar, un servicio de identidad acepta o rechaza credenciales desde un cliente, y el acceso a un portal interno exige además un código de un solo uso que no se puede reutilizar.

    A.2 Servidor de identidad y cliente de prueba

    1. Crea docker-compose.yml con el servidor RADIUS en 10.40.0.10 y un cliente en 10.40.0.20.
    services:
  radius:
    image: freeradius/freeradius-server:3.2.3
    container_name: lab-b2-radius
    networks:
      lan:
        ipv4_address: 10.40.0.10
    volumes:
      - ./radius/clients.conf:/etc/freeradius/clients.conf:ro
      - ./radius/authorize:/etc/freeradius/mods-config/files/authorize:ro
  cliente:
    image: alpine:3.20
    container_name: lab-b2-cliente
    command: sleep 3600
    networks:
      lan:
        ipv4_address: 10.40.0.20
networks:
  lan:
    driver: bridge
    ipam:
      config:
        - subnet: 10.40.0.0/24
    Captura prevista para la prueba de la Fase 5: pantalla del paso «A.2 Servidor de identidad y cliente de prueba» con la salida real. Se guarda en imagenes/B2-02.png.

docker compose ps

    Salida esperada: dos servicios arriba. Captura: docker compose ps.

    A.3 Que el servicio acepte y que rechace

    1. Pide autenticación con la clave correcta.
      docker exec lab-b2-cliente radtest ana ClaveAna2027 10.40.0.10 0 secreto-del-laboratorio
    2. Pide autenticación con una clave equivocada.
      docker exec lab-b2-cliente radtest ana clave-equivocada 10.40.0.10 0 secreto-del-laboratorio || true
    3. Pide autenticación con un usuario que no existe.
      docker exec lab-b2-cliente radtest desconocido Cualquiera1 10.40.0.10 0 secreto-del-laboratorio || true

    Salida esperada: Received Access-Accept en el primer caso y Received Access-Reject en los otros dos. Captura: los tres resultados seguidos, con el comando a la vista.

    Los dos rechazos deben ser indistinguibles para quien prueba: mismo mensaje, mismo tiempo aproximado. Si el de usuario inexistente tarda mucho más o dice otra cosa, el servicio está filtrando qué cuentas existen.

    A.4 Qué queda registrado

    1. Mira el registro del servidor para los tres intentos.
      docker logs lab-b2-radius 2>&1 | grep -E "Login OK|Login incorrect|bienvenid" | tail -6
    2. Comprueba que no aparece ninguna clave.
      docker logs lab-b2-radius 2>&1 | grep -c "ClaveAna2027" || true

    Salida esperada: líneas de Login OK y Login incorrect con el nombre de usuario, y un 0 en el segundo comando. Captura: las líneas del registro y el 0.

    Parte B — Segundo factor que no se puede reutilizar

    B.1 Secreto y primer código

    1. Genera un secreto base32 para el usuario ana y guárdalo en ana.secreto.
      head -c 20 /dev/urandom | base32 | tr -d "=" > ana.secreto
cat ana.secreto
      Captura prevista para la prueba de la Fase 5: pantalla del paso «B.1 Secreto y primer código» con la salida real. Se guarda en imagenes/B2-03.png.
    2. Genera el código de seis dígitos del momento.
      sudo apt-get install -y oathtool
      oathtool --totp -b "$(cat ana.secreto)"
    3. Comprueba que el mismo paso da el mismo código y que cambia al siguiente.
      oathtool --totp -b "$(cat ana.secreto)"; sleep 31; oathtool --totp -b "$(cat ana.secreto)"

    Salida esperada: un secreto en mayúsculas, un código de seis dígitos y, tras esperar, un código distinto. Captura: el secreto tapado y los dos códigos.

    El secreto es de este laboratorio y se queda en la VM. En un sistema real no se enseña, no se pega en el chat y no se guarda en el repositorio.

    B.2 Portal que exige clave y código

    1. Copia el portal del paquete del laboratorio y dale permisos de ejecución.
      asur-lab iniciar b2 && cp ~/labs/b2/portal.py .
chmod +x portal.py
    2. Pide acceso solo con la clave: debe rechazar por falta de código.
      python3 portal.py --correo ana --clave ClaveAna2027 || true
    3. Pide acceso con clave y código válido.
      CODE=$(oathtool --totp -b "$(cat ana.secreto)") && echo -n "$CODE" > ultimo.codigo && python3 portal.py --correo ana --clave ClaveAna2027 --codigo "$CODE"
    4. Repite el mismo código: debe rechazarlo por reutilizado.
      python3 portal.py --correo ana --clave ClaveAna2027 --codigo "$(cat ultimo.codigo)" || true

    Salida esperada: RECHAZO falta el segundo factor, luego ACCESO CONCEDIDO, luego RECHAZO codigo ya usado. Captura: los tres resultados en orden.

    B.3 Qué demuestra el montaje

    SituaciónResultado esperadoPor qué
    Clave correcta, sin códigoRechazoEl portal exige los dos factores
    Clave correcta y código del momentoAccesoLos dos factores son válidos
    Mismo código otra vezRechazoEl código se marcó como usado
    Código de otro usuarioRechazoEl secreto no corresponde a esa cuenta
    Clave correcta y código de hace diez minutosRechazoFuera de la ventana de validez

    Entregable y comprobación

    Entrega informe-b2.md con: los tres resultados de radtest, las líneas del registro sin claves y el 0 del conteo, los cuatro resultados del portal en orden y una frase por cada fila de la tabla de arriba diciendo si se cumplió.

    asur-lab check b2-identidad (desde el mismo directorio donde creaste el portal y su estado) comprueba que el servicio de identidad acepte la credencial válida, rechace la inválida y la de una cuenta inexistente, que el portal no conceda acceso sin segundo factor, que un código reutilizado se rechace y que los registros no contengan claves. No publica los valores esperados: si algo falla, señala el paso a revisar.
